# NEXMAX IT QUEST 全体設計（第2版 2026-11-21）

カンボジアの IT 学生（日本語は N4 学習中）が、3D のバーチャル空間で「日本で働く日々」を体で覚えるアプリ。
nexmax-academy（文字と絵の e ラーニング）の姉妹アプリで、こちらは **体験（歩く・押す・選ぶ・まちがえる）** が主役。
PC のブラウザで遊ぶのが基本。VR（WebXR）は後で足せるように作っておく。

元になった要望: tomy さんの企画メモ（`docs/企画メモ/`。タイトル画像・ボタンのイメージ・ステージ1と入社式の流れ）。
第1版を Fable 5.2 にレビューしてもらい、採り入れたものを「（Fable）」と書いた。

## 1. 技術の構成

| 何のため   | 使うもの                                                        | 理由                                                                                                                      |
| ---------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 画面の土台 | Vite + React 19 + TypeScript                                    | 3D が主役の1ページのアプリなので、Next.js（サーバーで組み立てる仕組み）は要らない。ビルドすれば静的なファイルだけで配れる |
| 3D         | three.js + React Three Fiber + drei                             | 企画メモの指定（threeJS）。キャラメイクの参考（r3f-ultimate-character-configurator）も同じ組み合わせ                      |
| VR（後で） | @react-three/xr                                                 | 同じ React Three Fiber の上で WebXR に入れる。今は入れない（7章）                                                         |
| 状態       | zustand（端末に保存）                                           | 進み具合・アバター・ICOCA の残高・メモ。顔写真だけは大きいので IndexedDB                                                  |
| 教材の形   | zod                                                             | academy と同じ。台本・豆知識・路線・駅の看板の中身を決まった形で持ち、機械でチェックする                                  |
| 見た目     | Tailwind CSS v4 ＋ 丸ゴシック（M PLUS Rounded 1c を自前で配る） | academy と同じ字体                                                                                                        |
| ログイン   | Supabase（Google ログイン）                                     | academy と同じ方式。設定が無いときはログインなし（デモモード）で動く                                                      |
| AI         | Gemini（使う人が自分のキーを入れる方式）                        | academy と同じ。キーは端末の中だけ。ステージ1では使わない（入社式の「セリフを言ってみよう」から）                         |
| 3D の部品  | polyfork（低ポリゴンの 3D モデル集）                            | 企画メモの指定。無料のモデルの GLB は CC BY 4.0 で、クレジットを付ければ公開リポジトリに置ける                            |
| 音         | WebAudio でその場で作る                                         | 目覚まし・ピッ・バイブ・チャイム。ブザーは作らない（Fable）                                                               |

## 2. 画面の流れ

```
タイトル ──(はじめて)── 設定（必須がそろうまで、押せるのは「設定」だけ）
   │
   ├─ ストーリー（はじめの話。1画面1文）
   └─ スタート（ダイブする）→ ダイブの演出 → ステージ選択 → ステージ → 修了証 → ステージ選択
```

- **タイトル**: tomy さんのタイトル画像を背景にし、ボタンのイメージ（2つの文・スタート・ストーリー・設定）を、
  その画像を測った位置・大きさ・色・字体（Noto Sans JP の太字）で HTML で重ねる（ふりがなが付く。文はボタンのイメージのとおりで、分かち書きの空白は入れない）。
  アプリの名前はタイトル画像の「NEXMAX IT QUEST」。スタートを押せない間は、設定のボタンを黄色く光らせ、下に「はじめに「設定」をしましょう。」を出す。
- **設定**: 名前（カタカナ）・ニックネーム・顔写真（カメラで撮る／画像を選ぶ・消せる）・Google ログイン・Gemini の API キー（つながるかを確かめる）・画面（ふりがな・軽さ・文字の大きさ・音）。
  - 必須は「名前・ニックネーム」と、Supabase の設定があるときの Google ログイン。
  - **Gemini のキーはステージ1の前には必須にしない**（ステージ1では使わないため。キーの無い学生や学校の回線が入口で止まらないように。Fable）。ステージ2の手前で求める。
  - 顔写真は NMChat の自分のアイコンと修了証に使う。端末の中だけに置き、サーバーにも Gemini にも送らない。3D の顔には貼らない（Fable）。
- **ダイブの演出**: タイトル画像の渦と同じ色の光の筋が手前に流れ、白く光ってステージ選択へ（約3秒・飛ばせる・動きを減らす設定では省く）。
- **ステージ選択**: ステージ1（入社初日）、ステージ2（入社式・準備中）。「つづきから」「はじめから」「章から はじめる」「修了証を 見る」。
- **いつでも開けるメニュー**: NMChat・路線図・メモ・持ち物（ICOCA と残高）・豆知識ずかん・着がえ・設定・ステージをやめる。

## 3. ステージの作り方（台本と場面）

- ステージは **台本（JSON）** と **3D の場面（プログラム）** に分ける。台本が進行と文を決め、場面は台本が待っている合図を出すだけ。
  - 台本: ステージ → 章 → 場面（section）→ 1こま（beat）。1こまの種類は say（セリフ1文）・objective（いま する こと）・wait（合図を待つ。ちがう合図には else の台本で答える）・tip（豆知識）・choice（選ぶ）・panel（NMChat などの画面）・focus（アップ）・fx（場面への演出の合図）・verdict（正解・不正解）・dream（思いうかべる）・jump（場面ごとやり直す）など。
  - 場面からの合図: `click:<物>`（物の前まで歩いてから出る）・`reach:<地点>`・`ticket:purchased` など。
  - **「アップになる」は camera の座標ではなく focus(物) で書く**（VR ではカメラを勝手に動かせないので、PC は寄る・VR は拡大の板を出す、と実装だけ替える。Fable）。
- **場面の始めで自動で保存**する。どの場面からでも保存データだけで始められる（つづきから・章から・テスト）。
- **画面の日本語は src/ に書かず、content/ に置く**（ui.json など）。lint:content が src/ の中の日本語の文字列を見つけたら止める。ふりがなの付け忘れを機械で漏れなく見るため（Fable）。
- テストと開発のときだけ、`window.__quest` から合図を送れる（3D の画素をクリックせずに最後まで通す。Fable）。

## 4. ステージ1「入社初日：ネクストメイクに行きましょう！」

台本と場面の一覧は `docs/design/01_ステージ1.md`。要点だけ書く。

- 家の駅は **天王寺**（御堂筋線 M23・谷町線 T27・JR）。改札が線ごとに分かれていて、どの改札に入るかで迷える駅にした。
- 会社の駅は **阿波座**（中央線 C15）。住所は academy の会社研究の資料と同じ（大阪市西区阿波座2丁目2-18 NANKAI西本町ビル 7F）。
- 行き方: 天王寺 →（御堂筋線・なんば・梅田方面）→ 本町で乗りかえ →（中央線・コスモスクエア方面）→ 阿波座。
- 3つの章に分ける（N4 の読む速さだと通しで 30〜45分かかるため。Fable）: 1 朝の家／2 駅まで・定期券／3 電車で会社へ。
- **改札とホームを選ぶ場面では、答えに矢印を出さない**（標識を読んで選ぶのがこのステージの中心。Fable）。止まっていると、ヒントが3段で出る（方向 → 見る看板 → 答えに近い1文）。
- まちがえた電車に乗ったら、天王寺は「券売機の前からやり直し」（企画メモ）。本町は「ホームからやり直し」（ここはヒントなしの本番。Fable）。
- 書く練習（選択式にしない）: 家の駅と線をメモする・着いたらヘンディさんに NMChat で連絡する（Fable）。判定は学生に有利に（漢字・かな・ローマ字のどれでも通す）。
- 修了証に「きょうの ことば」6語（定期券・改札・方面・乗りかえ・番線・押しボタン）を載せる（Fable）。
- 押しボタンの信号に矢印信号が付くのは実際にはめずらしいが、企画メモの順番どおりに1つの交差点にまとめた。画面のすみに「じっさいの 駅や 町と ちがう ところが あります。」を出す。
- 大阪メトロのロゴと ICOCA の絵柄（商標）は描かない。線のマーク（丸に M）と、青い地に名前だけのカードにした（Fable）。

## 5. 学生向けの日本語（academy から持ち越したルール）

詳しくは `docs/constraints.md`。

- 文は N4 学習中のレベル。1画面1文、1文30字まで（分かち書きの空白こみ）。3D では「1つの空間で、決めること1つ・読む看板1つ」と読みかえる（Fable）。
- **漢字には全部ふりがな**。読み方のデータ（`content/furigana.json`）から表示のときに付ける。難しい言葉をひらがなにしない（N5 を超える言葉は英語を添える）。
- 学生向けの文は文節の間に半角スペースを入れる（分かち書き）。
- 判定ははっきり書く（「不正解。」＋次にすることを1つ）。叱る音・ブザーは使わない。
- 「タイ」という国名を使わない。失敗する例を、名前のある登場人物にやらせない。

### 6.2 タイトル画像と低ポリゴンをつなぐ

タイトル画像（つやのあるアニメ調）と 3D（低ポリゴン）は、無理に同じ絵柄にしない。「ダイブした先の世界は低ポリゴン」と割り切り、
色と光の記号だけをそろえる（濃い青・シアンの光・白・桜色。画面の板は「ガラスの板＋シアンの縁」。クリックした所に出る輪は、タイトル画像のネクマックスの足元の輪と同じ形）。（Fable）

### 6.3 景色をにぎやかにする部品

- 町（`src/stages/stage1/town.tsx`）: Little Tokyo の部品を、キットの決まり（4m のます目・1階 3m・正面は +z）で手で並べる。
  同じ部品をたくさん置くときは `Many`（まとめて描く）。木は季節で入れかえる（`SeasonTrees`。季節は `src/lib/season.ts`）。
  ゲームの中の日は入社式の 4月1日（台本の `day`。tomy さん 2026-11-23）なので春: 並木も桜にし、花びらが散って地面にもつもる（`src/factory/season-parts.tsx`）。
  夏はイチョウと桜の緑の葉、秋はイチョウを黄色・桜を紅葉の色に（頂点の色を置きかえる。`src/factory/props.tsx`）、冬は葉の落ちた木（polyfork の Bare Mountain Rowan）。
  確かめるときは URL に `?season=autumn` のように付けると、その季節で見られる。
- 景色の看板の字は、かなだけを工場で描く（`src/factory/town-parts.tsx`）。polyfork の飾りの漢字はふりがなを付けられないので消す・使わない。
- 地下の駅（`src/factory/subway-parts.tsx`）: 「8番出口」のオマージュ。白いタイルのかべ・同じポスターの列・長い蛍光灯・黄色の「出口 8」の看板。
  ポスターの文は `content/ui.json` の poster.*（ふりがなは読み方のデータから）。ポスターの絵は形だけで、人の顔やキャラクターは描かない。
- 柱は、カメラと自分の間に入ると、うすく透ける（前が見えなくならないように）。
- 通行人は道を行き来する（`Walkers`）。「かるい」設定では半分にする。

### 6.4 polyfork の決まり

- 無料のモデルの GLB は CC BY 4.0。`CREDITS.md`（と `public/credits.txt`）にクレジットを自動で書く。
- `.mjs`（形を変えられるプログラム版）と HD 版は公開リポジトリに置かない（ライセンスで禁止）。
- 形の変更（体型を女性に、など）は polyfork のバリエーションの GLB を取り寄せて置く。
- MCP の設定は `.mcp.json`（`https://polyfork.dev/mcp`）。

## 6.9 色合い（パステル）

- 色彩感のベースは「どうぶつの森」（tomy さん 2026-11-23）。全体に明るく・パステルで・やわらかく。黒を出さない。
- 町・駅・電車の部品は、みんな1つの素材 FLAT（`src/factory/kit.ts`）を通す。`pastelize` が2つの処理を足す:
  1. 素材の色（頂点の色）を少し あたたかい白に寄せる（lift 0.1）。色の こさは少し上げる（sat 1.08。白っぽくなって灰色に見えないように）。
  2. 光が当たったあとの色を、いちばん暗い所 → うすい あたたかい灰色、いちばん明るい所 → クリーム色 に おさめる（コントラストを やわらかく）。
- 建物の かべは、灰色・白っぽい明るめの面だけをパステルの色に置きかえる（`pastelWall`。窓・屋根・看板の こい色は そのまま）。
- あかり（`Lights`）は どの場面も明るめ・下からの光も明るく。空はパステルの水色、トンネルは まっ黒にしない。
- アバターの服と髪も少しパステルにする。はだの色は変えない（はだを白くしない。Fable）。
- 看板・電光掲示板・券売機の画面（CanvasPanel）は、この処理を通さない（字を読みやすく）。

## 7. アバター（キャラクターメイキング）

- 体・服・髪は**ブレンダー**で作る（`tools/blender/build_avatar.py` を画面なしで動かすと `public/models/avatar/avatar.glb` ができる。2026-11-23）。
  2〜3頭身・大きな頭・短い手足・まるい形・やわらかい陰（4段）。tomy さんの指示「どう森のような感じ」（2026-11-21）・「ブレンダーで調整できる？」（2026-11-23）。
  ライセンスがはっきりしてスーツもある素材が無かったため、自分で作る。
- 1つの GLB に、全部の服・髪型・かざりの部品が入っている。部品の名前の頭で色を決め、設定に合う部品だけを出す（`src/three/avatar-parts.ts`）。
  腕・足は付け根が原点で、`Chibi.tsx` がそこを中心に回す。町の人が多いので、髪いがいの部品は三角を 約1,500 までにへらす。
  ファイルは Draco で小さくする（約1.4MB）。読み手は外のサーバーでなく `public/draco/` に置いたものを使う。
- 体の形は3つ: 男性・ズボン／女性・スカート／女性・ズボン（女性の胴は、肩を少しせまく・こしを少し細く）。
- 髪は、頭にかぶる厚みのある1つのかたまり（`cap`）で作る。下のはし（切りそろえた線）とふくらみを髪型ごとに決め、はしは厚くまるくする。
  前髪は大きな毛先2〜3つか、まっすぐな切りそろえ。つんつん・くるくるは、かたまりの上に こぶを足す。髪のはしが がたがたになるので、髪は三角をへらさない。
  着がえの髪型のボタンには髪型の絵を出す（`tools/blender/render_hair_icons.py` → `public/img/hair/`）。
- 学生・主要キャラ（`content/characters.json`）・まわりの人（色・髪型・身長・目をばらけさせる）を、全部同じ部品で作る。
- 顔は Canvas に描いて頭の球に貼る（目・まゆ・口・ほっぺ）。まばたきは、目を閉じた顔に一瞬だけ取りかえる。
  目・まゆ・鼻・口・ほっぺは、GPT（Codex の画像生成）で作ったパーツの表を切り出して貼る（`src/three/face-parts.ts`。頼み方と切り出し方は `docs/codex/face_parts.md`）。
  絵が読みこめないときだけ、プログラムで描いた仮の顔を出す。
- 服には Codex で作った布の模様を灰色にして、選んだ色にかける（スーツ＝ツイル・パーカー＝ニット・ふだんのズボン＝デニム・ふだんのスカート＝チェック。
  `scripts/make_fabrics.py` → `public/img/fabric/`）。ブレンダーの回転体の部品に UV を付けてある（1 = 0.25m）。
- 動きは骨を使わず、体・頭・腕・足の部品を回す（立つ・歩く・走る・すわる・話す・うなずく・おじぎ・おどろく）。
- 形は Codex で作った参考の絵（`codex_out/avatar_*.png`。2026-11-22）に合わせた: こげ茶のふちの線・大きな目と2つの光・額にかかる前髪の束・横に出た耳・
  スーツのえりとシャツの V・女性のリボンとストッキング・パーカーのひもとリュック。
- 服に「着ぐるみ」（くま・ねこ・うさぎ）がある（tomy さん 2026-11-23）。胴・手足は ふだんの服と同じ形で色だけ変え、耳つきのフード・おなか・しっぽを足す。
  フードで髪と人の耳をかくす。入社式の日はスーツでないと決定できないのは同じ。
- くつは3つの形（革ぐつ・スニーカー・サンダル。`shoeType`）。無ければ スーツは革ぐつ・ふだんの服はスニーカー。着ぐるみは どうぶつの足。
- 顔（頭の球）は、ほっぺを ふっくら横に広げ、あごを まるく少し平らにした形（`Chibi.tsx` の faceShape）。上の半分は 髪に合わせて まるいまま。

## 8. 動かし方（PC）と VR への準備

- PC: 床をクリックするとそこへ歩く（光る輪が出る）。WASD・矢印キーでも歩ける。光る物はクリックすると、その前まで歩いてから反応する。
  カメラは自分の後ろから追い、歩く向きへ自動で回りこむ。ドラッグで左右を少し見回せる。部屋が狭い所（家・電車の中）は決まったカメラ。
- タッチでも同じ操作で動く（ホバーに頼らない）。
- VR の準備（今から守っていること）:
  1. 進むのに要る情報は 3D の中に置く（看板・電光掲示板・券売機の画面）。券売機は最初から 3D の中に Canvas で描き、押した所で操作する（Fable）。
  2. クリックは R3F の onClick だけで作る（drei の Html と DOM のイベントを 3D の操作に使わない）。VR ではコントローラーの光線が同じ合図になる（Fable）。
  3. 移動は「地点＋歩ける四角」で持つ（物理エンジンを使わない）。VR のテレポート先にも使える。階段は場面の切りかえにする（縦に動くと酔うため。Fable）。
  4. セリフ・豆知識・選択肢はデータで持ち、今は HTML で出す。VR では同じデータを 3D の板に描く（描き手だけ足す）。
  5. 光の色調補正やブルームに頼らない（重い）。Canvas は1つを使い回し、場面だけを入れかえる。

## 9. 低い性能の PC と回線

- 「画面の きれいさ」を「かるい」にすると、解像度を下げ、まわりの人を半分にする。
- 影は使わない。部品はまとめて描く（描画の回数を減らす）。
- 3D のモデルは場面ごとに読みこむ。ビルドしたプログラムは圧縮して約 0.5MB。モデルは全部で約 5MB（人はプログラムで作るので、モデルは要らない）。
- WebGL が動かないときは「この パソコンでは 3Dが 動きません。先生に 伝えて ください。」を出す。

## 12. 公開

- 今は **GitHub Pages**（一時の公開先）。先々 **Cloudflare** に移す（tomy さん 2026-11-21）。
- アプリは静的なファイルだけで動く（`npm run build` → `dist/`）。サーバーの処理は持たない。だから置き場所を変えても中身は変わらない。
- GitHub Pages: `.github/workflows/pages.yml`。リポジトリのふだんの枝（default branch）に push したときに公開する。
  - URL の頭にリポジトリの名前が付く（`/nexmax_it_quest/`）。ビルドのときに `VITE_BASE` で渡し、絵・3D の部品・字体・ページの切りかえ（wouter の base）を全部これに合わせる。
    プログラムの中で URL を書くときは、`import.meta.env.BASE_URL`（または `src/lib/env.ts` の `BASE_URL`）を頭に付ける。`/img/...` のように頭から書かない。
  - GitHub Pages には「どの URL でもアプリを返す」設定が無い。`index.html` を `404.html` にも写し、`/nexmax_it_quest/stages` などを直接開いても動くようにした。
  - Supabase の値（`VITE_SUPABASE_URL` など）は、まだ入れていない。入れるまでは、ログインなしで動く。
- Cloudflare に移すとき:
  1. `VITE_BASE` を渡さずにビルドする（頭は `/`）。
  2. 「無いページはアプリ（`index.html`）を返す」設定にする（Workers の静的ファイルなら `not_found_handling = "single-page-application"`）。`404.html` は作らない。
  3. Supabase を使うなら、ログインのあとに戻る URL（`<公開の URL>/settings`）を Supabase の許可の一覧に足す。
  4. GitHub Pages の公開を止める（`.github/workflows/pages.yml` を消す）。

## 2. 決めたこと

### 1人か、みんなでか → みんなで（1〜4人）。1人でも遊べる

- **今回作る形（段階1）: 1台のパソコンを 1〜4人で囲む**。academy の WATER FALL QUEST（`quest-setup.tsx`）と同じ形を元にする。
  - いっしょに遊ぶ人を えらぶ: ログインしていれば、同じ学校・期生の一覧（DB の関数。入社式の席と同じ）から。ログインしていない・DB が止まっているときは、ニックネームを入れる。
  - 質問の時間は、順番にマイクを回す（「🎤 つぎは ○○さんの 番」）。ホワイトボード（わかったこと）は みんなで1つ。全員が1回は質問する。
  - 理由: (1) academy で動いている形で、同じ学校・期生の一覧の関数も そのまま使える。(2) 通信が ほとんど要らない（Supabase の通信量の上限を気にしなくてよい。止まっていても遊べる）。
    (3) N5 の人は、となりの人と相談しながらのほうが 質問を作りやすい。(4) 1人のときも同じ画面で遊べる。
- **次の段階（段階2。設計だけ）: べつべつのパソコンから、同じ会議室に入る**。Supabase の Realtime（Broadcast と Presence）で、
  「だれの番か・質問・開いたカード」を配る。画面（MeetingPanel）は同じで、同期の部品（下の `TeamSync`）だけ入れかえる。
  Supabase が動くようになってから作る（今は止まっていて、ためせないため）。

### チームのデータの持ち方

- 端末に保存する（いつでも つづきから）。**節目だけ DB に書く**（ミーティングが終わったとき。academy の `quest_saves` と同じ考え方）。
- DB の表 `itquest_team_saves`: メンバーの組（1〜4人）とステージで1行。`state`（下の形）を丸ごと入れる。メンバーだけが読み書きできる。管理者は読める（先生が「だれが 何を 聞いたか」を見られる）。
  メンバーの組の鍵は academy の `quest_member_key()` を使う。ニックネームだけの人が入っている組は、端末だけに保存する。
  作り方は `supabase/migrations/`（**まだ DB には入れない。tomy さんの OK と、Supabase が動くことが要る**）。
- `state` の形（ミーティング1回分）:

```ts
interface TeamMeetingState {

```

- 同期の部品の形（今は「端末だけ」と「節目に DB」。段階2で Realtime を足す）:

```ts
interface TeamSync {
```

  正の状態は DB の行。書くのは DB の関数（行をロックして1つずつ足す）にして、あとから書いた人が前の人の分を消さないようにする。
  声は、質問した人の端末だけが Gemini Live につなぐ（ほかの人には文字が届く）。

### 「いい質問」を考えられる仕組み（N5 でも直感で分かるように）

1. **時間が足りない**: 山本社長の時間は30分。質問は**10回まで**（1回 = 3分。画面に ⏱ と のこりの回数）。必ず聞くことは8こ。
   もう聞いたこと・関係ないことを聞くと、回数が へる。→「何を先に聞くか」「メモを見てから聞く」を、体で覚える。
2. **ホワイトボード**（3D の会議室の かべ）: 左「わかった こと」（リスニングで聞いた4つ。緑）、右「まだ わからない こと」（絵文字つきの「？」カード8まい）。
   何を聞けばよいかは、絵文字と短い言葉で見える（🎯 ページの 目的・💰 給料・🚀 いつまでに 作る？ など）。答えは、聞くまで出ない。
3. **質問は自分の声で言う**（えらぶ形にしない。必ず守るルール3）。助けは3段: ①カードの絵と言葉 ②文の型（「＿＿は いくらですか。」）③お手本の文。押した分だけ出る。点は へらさない。
4. **コツを先に3つだけ**（絵文字つき）: 🗒️ メモを 見る（まだ 聞いて いない ことを 聞く）／✏️ はっきり 聞く（「何が」を 入れる）／🎯 ページに 要る ことを 聞く。
   質問の時間の前に「これは いい 質問ですか」を5問（👍／🤔 で答える。読む確認なので えらぶ形でよい）。
   よくない質問の例は、架空の新人（となりのチームの 山田さん・田中さん）の質問として出す（必ず守るルール8）。
5. **1回ごとに、絵文字と1文で返す**: ✨ 新しい ことが わかりました！／🗒️ もう 聞いた ことです／✏️ あと ひとこと／🧭 ページに 要らない 質問です／⏳ まだ 決まって いない ことです／⭐ いい 質問！（カードに無いことを聞き出した）。
   「なぜ・どうして・どんな」で聞いたときは「くわしい 話が 聞けます」と ほめる。
6. **かくれたボーナス4つ**（ホワイトボードに出ていない: 応募の あと・会社の 思い・なぜ プノンペン？・ページの 色）。自分で考えた質問で開く。
   「まだ 相談中です」と言われること（写真・英語の ページ・休み）もある。→「次の 会議で 聞く こと」に入る（本当の仕事と同じ）。
7. **おわりに**: 聞けたこと（ホワイトボード）が、そのまま「聞いた こと」のメモになる。聞けなかったカードには「次は こう 聞いて みよう」（お手本）を出す。
   星（5・7・8まい）。「もう 一度 ミーティングする」か「つぎへ」（行き止まりにしない。足りない分は「あとで メールで 聞きましょう」）。

### 本当の仕事の感じ

- NMChat にヘンディさんの連絡（お客さま・作るもの・14時・会議室A・30分）。メモと「やる こと」に入る。
- はじめて会うお客さまに、自分から名前を言って おじぎ（マイク）。おわりに「本日は ありがとうございました。会社で 整理して、また ご連絡します。」（マイク）と おじぎ。
- ヘンディさんとお客さまの話を聞いて メモを取る（リスニング）。聞いたことは、もう聞かない。
- 決まっていないことは「相談中」。全部は1回で決まらない。

## 4. 質問の時間の画面（`panel: meeting`。データは `content/meetings/aoba-kickoff.json`）

3D は、ホワイトボードと山本社長が**上の 55%** に見える向き（アップ `board`）。下に クリームのカードを2つ。

```
┌────────────────────────────────────────────────────────────────────────┐
│ いま すること: 山本社長に 質問しよう        ⏳ のこり 7回（21分）  [メニュー] │
│        ┌──────────── 3D の ホワイトボード ────────────┐                 │
│        │ わかった こと（緑）        まだ わからない こと     │                 │
│        │ 📍 プノンペン  👥 二人…     🎯？  🍵？  🏪？  ✅？   │  ← 押して えらべる │
│        │ 🌏 …  📮 …                📅？  💰？  🧾？  🚀？   │                 │
│        └──────────────────────────────────────────────┘                 │
│     山本社長（話す動き）   ヘンディさん    チームの 人（頭の上に 名前）       │
│ ┌─ 質問する 人（左 40%）────────┐ ┌─ 会話（右 58%）────────────────────┐ │
│ │ 🎤 つぎは ソピアさんの 番      │ │ 山本社長: では、聞きたい ことから どうぞ。 │ │
│ │ (ソク)(ソピア●)(ダラ)          │ │ ソク: 給料は いくらですか。            │ │
│ │ 聞く こと: 💰 給料  [かえる]   │ │ 山本社長: 茶道の 先生は 月 30万円からです。…│ │
│ │ ヒント: ＿＿は いくらですか。  │ │ ✨ 新しい ことが わかりました！          │ │
│ │ [ヒント]   [🎤 押して 話す]    │ │                                      │ │
│ └────────────────────────────────┘ └──────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────────┘
```

進み方:

1. **コツ**（`lesson`）: 3つのコツのカード → 「これは いい 質問ですか」5問（👍 いい 質問／🤔 よくない）。答えると 理由（`reason`）と、どのコツかが出る。
2. **質問**: 山本社長「では、聞きたい ことから どうぞ。」（`opening`）。番の人が、
   ホワイトボードの「？」（3D。押すと えらべる。下のカードにも同じ札）を えらぶ → マイクで質問（スペースを押す間、または マイクを押して もう一度押すまで）。
   えらばないで、自由に聞いてもよい（「自分で 考えて 聞く」）。
3. **見かた**（端末の中で決める。AI には決めさせない。academy と同じ）:
   1. 聞きとった質問を読みに直し、カードごとに 当たったキーワードを数える（読み・漢字の どちらでも）。
   2. えらんだカードのキーワードが 1つ以上 → そのカード。えらんでいない・合わない → いちばん多く当たったカード（2つ以上）。
   3. 「わかった こと」に当たる → `known`。「相談中」のこと → `undecided`。
   4. はっきり決まらないとき → 山本社長の返事（文字起こし）の中の印（`markers`: 50万・6月・笑顔 など）で決める。
      「関係が ありません」→ `offTopic`、「何に ついてですか」→ `unclear`。
   5. 読みで5字より短い質問は `unclear`（山本社長「すみません、何に ついてですか。もう 一度 お願いします。」）。
   - `content/meetings/aoba-kickoff.json` の `tests` に、質問の例と 当たるはずのカードがある。単体テストにする。
4. **カードが開く**: ホワイトボードの「？」が めくれて、絵文字と短い答え（`short`）が入る。会話には 山本社長の答え（`secret`。ふりがなが付く）。
   声は Gemini Live の山本社長（声 `Kore`。事実は `persona` に入れてある）。声の言い方が少し ちがっても、カードの文が正。
5. **回数**: 山本社長が答えた質問（new・bonus・known・offTopic・undecided）は 1回 使う。`unclear` は使わない（言い直せる。同じ人が2回つづけたら 次の人へ）。
6. **おわり**: 8まい全部 開く、または 回数が0 → 結果（星・開いたカード・聞けなかったカードの お手本・ボーナス・「次の 会議で 聞く こと」・だれが いくつ聞いたか）。
   「もう 一度 ミーティングする」か「つぎへ」。
7. キーが無い・マイクが使えないときは、`TalkPanel` と同じ案内（設定を開く・もう一度・ステージを出る）。
8. 自動テスト（`window.__fakeLive`）: 聞きとりの文は にせの台本から。山本社長の返事は、端末の見かたで決めた文（`secret`・`replies`）。

## 5. チームを作る画面（`panel: team`）

- 「1人で」／「みんなで（2〜4人）」。1人目は自分（かえられない）。
- ログインしていて DB が動いているとき: 同じ学校・期生の人の一覧から えらぶ（アバターも その人のもの）。
- それ以外: ニックネームを入れる（3人まで足せる）。見た目は、名前から決まる ちびキャラ。
- 説明の文:「1台の パソコンを みんなで 使います。順番に マイクで 質問します。」
- えらんだ人は、会議室の席に座る（頭の上に名前）。えらんだ順が、質問の順番。

## 6. 3D の場面

- **`office-floor`（ネクストメイクの オフィス。7階）**: つくえの島が2つ（ノートパソコン）、ヘンディさんの席、自分の席（`my-desk`。パソコンが光る）、植木、窓、エレベーターの戸（はじめに立つ所）、
  「会議室A」の戸（`door-a`。上に看板）。名前の無い社員が 2〜3人（座っている・歩いている）。明るい春の朝。
- **`meeting-room`（会議室A）**: 長いテーブル、キャスターの無いいす（入社式と同じ）8つ、かべに**ホワイトボード**（3.2m×1.7m くらい。Canvas で描く。カードを押せる）と モニター（リスニングの文を出す）、戸、窓、植木。
  席: ホワイトボードに近い側に 山本社長とヘンディさん（向かい合わせ）。手前に 自分とチームの人。
  アップの向き: `yamamoto`（あいさつ）・`talk-view`（リスニング。2人とモニター）・`board`（質問。ホワイトボードと山本社長）。
- **人**: 山本社長（40代の女の人。落ち着いた深い緑のジャケット・白いシャツ・ボブ。`content/characters.json` に足す）。話している人は「話す動き」。
- 絵（豆知識3つ・山本社長の顔・NMChat の Aoba の絵）は、まず 3D の部品を撮って作る。Codex への頼み方は `docs/codex/stage2_visuals.md`。

## 7. ステージ選択

- ステージ2のカードを足す。ステージ1をクリアすると開く（自動テストと開発では、はじめから開けられるようにする）。
- 修了証は、ステージごとの「きょうの ことば」を出せるようにする。

## 8. 確かめ方

- 単体テスト: 質問の見かた（`tests` の例）・回数・番の回り方・チームの保存の鍵。
- 最初から最後まで通すテスト（`e2e/stage2.spec.ts`）: チーム（2人）→ あいさつ → リスニング → コツの5問（1回まちがえる）→ 質問（新しい・もう聞いた・短い・ボーナス）→ 結果 → お礼 → 修了証。写真を残す。
- 画面の写真で、会議室・ホワイトボード・質問のカード・結果を見る。ステージ1が前と同じに通ること。
